What is TuitionStation?

TuitionStation is a location-based tuition marketplace built with Flask (Python) and Microsoft SQL Server. It connects students with qualified home tutors in their area. The platform supports three roles: Admin, Teacher, and Student.

Core Problem It Solves

Students struggle to find qualified home tutors — they rely on word-of-mouth or scattered ads. Teachers have no centralized way to connect with students. TuitionStation bridges this gap with a searchable, location-based marketplace.

How It Was Built (Step by Step)

  1. Planning: Identified core entities (User, Teacher, Student, Post, Application, Payment) and designed the database schema.
  2. Database Design: Created schema.sql with 12 tables, 7 stored procedures, 4 views, 5 triggers, and 11 indexes for SQL Server.
  3. Flask Project Setup: Used Flask app factory pattern (app.py) with blueprints for modular routing.
  4. Models Layer: Defined SQLAlchemy ORM models in models/__init__.py (12 model classes).
  5. Authentication: Built email/password auth with Flask-Login, plus Google and Facebook OAuth via Firebase.
  6. Admin Panel: Created admin blueprint with dashboard, user management, payment verification, and reports.
  7. Student Panel: Built tutor search, tuition posts, applications, reviews, saved tutors, and messaging.
  8. Teacher Panel: Built profile management, tuition browsing, applications tracking, analytics, and subscriptions.
  9. Subscription System: Implemented Free/Standard/Premium plan tiers with application limits.
  10. Payment System: Integrated bKash payment gateway (sandbox) and manual admin verification flow.
  11. Chat System: Built real-time messaging with read receipts and notification integration.
  12. Email System: SMTP-based welcome emails sent on registration.
  13. Firebase Integration: Added Firebase Auth for social login and Firebase Admin SDK for server-side operations.
  14. Frontend Design: Built a custom design system ("Tuition Station" style) with CSS variables, glassmorphism, and responsive layouts.
  15. Seeding: Auto-seeds admin, 12 sample teachers, 2 sample students, and subscription plans on first run.

🔧 Installation Guide

Step-by-step setup from scratch — get the app running on your local machine.

Prerequisites

  • Python 3.9+
  • Microsoft SQL Server (with SSMS)
  • ODBC Driver 17 or 18 for SQL Server
  • Git (optional)

Step 1: Clone & Navigate

cd E:\Level 2 term II\DBMS\tuition_system

Step 2: Create Virtual Environment

python -m venv .venv .venv\Scripts\activate

Step 3: Install Dependencies

pip install -r requirements.txt

This installs: Flask, Flask-SQLAlchemy, Flask-Login, Flask-WTF, pyodbc, Werkzeug, python-dotenv, requests, firebase-admin.

Step 4: Setup SQL Server Database

Option A: Using SSMS — Open schema.sql and execute it.

Option B: Command line:

sqlcmd -S localhost -E -i schema.sql

This creates tuition_station database with all 12 tables, stored procedures, views, triggers, indexes, and seed data.

Step 5: Configure Environment

The .env file should contain:

DATABASE_URL=mssql+pyodbc://localhost/tuition_station?trusted_connection=yes&driver=ODBC+Driver+17+for+SQL+Server SECRET_KEY=tuition-station-secret-key-2024 FIREBASE_API_KEY=your_key FIREBASE_PROJECT_ID=tuition-station FIREBASE_STORAGE_BUCKET=tuition-station.appspot.com FIREBASE_APP_ID=your_app_id

Step 6: Run the Application

python run.py

App runs at http://localhost:5000. On first run it auto-seeds:

  • Admin account (admin@tuition.com / admin123)
  • 3 Subscription Plans (Free, Standard, Premium)
  • 12 Sample Teachers with complete profiles
  • 2 Sample Students
Note: The app uses Windows Authentication (Trusted Connection) by default. If using SQL Server authentication, update DATABASE_URL in .env accordingly.

USE tuition_station; SELECT * FROM subscription_plans; -- Should show: Free, Standard, Premium

Database Migration Strategy

This project does not use Alembic or Flask-Migrate. Schema changes should be made directly to models/__init__.py and schema.sql in parallel. On startup, db.create_all() is called but does NOT alter existing tables — it only creates new ones.

🔐 Authentication System

How user authentication, role management, and access control work.

Authentication Flow

  1. Registration: User fills form at /register. For teachers, profile is created but is_approved=False — admin must approve.
  2. Login: Email + password verified via User.check_password() (Werkzeug hashing).
  3. Session: Flask-Login manages session with login_user() and @login_required decorator.
  4. Redirect: After login, users are redirected to their role-specific dashboard.
  5. Logout: logout_user() clears the session.

Role-Based Access Control

Each blueprint uses a role-checking decorator:

def admin_required(f): @wraps(f) def decorated(*args, **kwargs): if not current_user.is_authenticated or current_user.role != 'admin': flash('Access denied.', 'error') return redirect(url_for('auth.index')) return f(*args, **kwargs) return decorated

Similar decorators exist in each blueprint: admin_required (admin.py), student_required (student.py), teacher_required (teacher.py).

Password Security

def set_password(self, password): self.password_hash = generate_password_hash(password) def check_password(self, password): return check_password_hash(self.password_hash, password)

Uses Werkzeug's generate_password_hash with scrypt (default).

Approval Flow

  • Students are auto-approved on registration.
  • Teachers require admin approval before they can log in.
  • Admins approve from the Users management page.
  • Approval sends a notification to the teacher.
  • Blocked users (is_active=False) cannot log in.

Login Restrictions

if user and user.check_password(password): if not user.is_active: flash('Account blocked. Contact admin.', 'error') elif user.role == 'teacher' and not user.is_approved: flash('Your account is pending admin approval.', 'warning') else: login_user(user)

🔥 Firebase Integration

How Firebase is used for authentication, storage, and social login.

Architecture

Firebase is used in two ways:

  • Client-side: Firebase Auth SDK (in base.html) for Google/Facebook login
  • Server-side: Firebase Admin SDK (firebase_config.py) for initialization

Client Setup (base.html)

<script src="https://www.gstatic.com/firebasejs/10.7.1/firebase-app-compat.js"></script> <script src="https://www.gstatic.com/firebasejs/10.7.1/firebase-auth-compat.js"></script> <script> const firebaseConfig = { apiKey: "{{ config.FIREBASE_API_KEY }}", authDomain: "{{ config.FIREBASE_PROJECT_ID }}.firebaseapp.com", projectId: "{{ config.FIREBASE_PROJECT_ID }}", storageBucket: "{{ config.FIREBASE_STORAGE_BUCKET }}", appId: "{{ config.FIREBASE_APP_ID }}" }; firebase.initializeApp(firebaseConfig); window.firebaseAuth = firebase.auth(); </script>

Server Setup (firebase_config.py)

def initialize_firebase(): if not firebase_admin._apps: cred_path = 'tuition-station-firebase-adminsdk-....json' if os.path.exists(cred_path): cred = credentials.Certificate(cred_path) firebase_admin.initialize_app(cred, {'storageBucket': bucket_name})

Social Login Flow

  1. User clicks Google/Facebook button on login page
  2. Firebase client SDK handles OAuth popup
  3. Access token is sent to server via POST
  4. Server verifies token via Google/Facebook API
  5. If user exists, log them in; if not, create account
  6. Return JSON response with redirect URL

Google Login Route

@auth_bp.route('/google-login', methods=['POST']) def google_login(): data = request.get_json() access_token = data.get('access_token') resp = requests.get('https://www.googleapis.com/oauth2/v3/userinfo', headers={'Authorization': f'Bearer {access_token}'}) google_data = resp.json() email = google_data.get('email') user = User.query.filter_by(email=email).first() if not user: user = User(name=name, email=email, role=role, ...) db.session.add(user) login_user(user) return jsonify({'success': True, 'redirect': redirect_url})

Facebook login works similarly using the Facebook Graph API.

🔗 Social Login

Google and Facebook OAuth integration details.

Google Sign-In

Endpoint: POST /google-login

Request: JSON with access_token and role

Verification: Calls Google's /oauth2/v3/userinfo API

Auto-creation: Creates new user if email doesn't exist, assigns Free subscription for teachers

Facebook Login

Endpoint: POST /facebook-login

Request: JSON with id_token and role

Verification: Calls Facebook's /me?fields=id,name,email,picture API

Fallback email: If Facebook doesn't provide email, uses {fb_id}@facebook.com

Payment Verification Flow

  1. Teacher submits payment with transaction ID
  2. Payment appears as "Pending" in admin panel
  3. Admin clicks Approve → system:
    • Sets payment.status = 'Approved'
    • Deactivates any existing active subscription
    • Creates new subscription with plan's duration
    • Sends notification to teacher
    • Logs the action in admin_logs

Reports (/admin/reports)

  • Monthly revenue breakdown (year, month, transaction count, total revenue)
  • Plan distribution stats (how many active subscribers per plan)

Activity Logging

💳 Payment System

bKash payment gateway integration and manual payment flow.

Payment Flow

Teacher selects plan → Chooses bKash/Nagad → Enters TXN ID → Admin verifies → Subscription activated

Manual Payment (Default)

  1. Teacher clicks "Subscribe" → redirected to /payments/request/<plan_id>
  2. Fills in: method (bKash/Nagad), sender number, transaction ID
  3. Payment saved with status "Pending"
  4. Admin verifies on /admin/payments
  5. On approval → subscription activated, user notified

bKash API Integration

bkash_config.py implements the bKash Tokenized Checkout API:

  • Sandbox URL: https://tokenized.sandbox.bka.sh/v1.2.0-beta/tokenized
  • grant_token() → Gets ID token for API auth
  • create_payment() → Creates payment and returns bKash URL
  • execute_payment() → Executes payment after user completes in bKash app
  • query_payment() → Checks payment status

When bKash is not configured (no API keys), the system runs in demo mode — payments are auto-approved:

if not BkashConfig.is_configured(): # Create payment as Pending # Return demo: true and redirect to payment_success return jsonify({'success': True, 'demo': True, ...})

💬 Chat System

Direct messaging between students and teachers.

Architecture

The chat system uses a simple database-driven messaging model:

  • Messages stored in messages table
  • Each message has sender_id, receiver_id, message text, is_read flag, read_at timestamp
  • Conversations are grouped by the other participant
  • No WebSocket — uses traditional request-response
  • Unread count available via API: /chat/api/unread

Routes

Conversation Grouping Logic

for m in sent: other_id = m.receiver_id if other_id not in conversations: other = User.query.get(other_id) conversations[other_id] = {'user': other, 'last_msg': m.created_at, ...} for m in received: other_id = m.sender_id # Same logic — merge with existing if found

Read Receipts

When a user opens a conversation, all unread messages from that sender are marked as read:

🚀 Deployment

Options for deploying TuitionStation to production.

  1. Install IIS with CGI feature
  2. Install wfastcgi Python package
  3. Configure IIS handler for Flask
  4. Deploy the project to inetpub/wwwroot

Option 2: Azure App Service

  1. Create Azure Web App (Python stack)
  2. Configure SQL Server Database in Azure
  3. Update DATABASE_URL with Azure SQL connection string
  4. Deploy via Git or FTP

Option 3: Docker

FROM python:3.9-slim WORKDIR /app COPY requirements.txt . RUN pip install -r requirements.txt COPY . . CMD ["python", "run.py"]

Production Considerations

  • Set debug=False in run.py
  • Use a production WSGI server (Gunicorn, Waitress, or uWSGI)
  • Set strong SECRET_KEY in environment
  • Enable HTTPS via reverse proxy (Nginx, Azure Front Door)
  • Configure proper SQL Server firewall rules
  • Set up scheduled task for sp_AutoDowngradeExpiredSubscriptions

🐛 Troubleshooting

Common issues and their solutions.
Database Connection Error
Error: ('08001', '[08001] SQL Server Network Interfaces...')

Fix: Ensure SQL Server is running and TCP/IP is enabled:

  1. Open SQL Server Configuration Manager
  2. SQL Server Network Configuration → Protocols for MSSQLSERVER
  3. Enable TCP/IP
  4. Restart SQL Server
ODBC Driver Error
Error: ('01000', "[01000] [Microsoft][ODBC Driver Manager]...")

Fix: Download and install "ODBC Driver 17 for SQL Server" from Microsoft.

Port 5000 Already in Use
netstat -ano | findstr :5000 taskkill /PID /F

Alternatively, change the port in run.py.

Firebase Not Working
  • Verify .env has correct Firebase credentials
  • Ensure serviceAccountKey.json is in the project root
  • Check Firestore database is created in Firebase Console
Sample Data Not Created

Manually run:

python seed.py

Or restart the app — data is seeded on first run only if tables are empty.

Module Not Found

Ensure virtual environment is activated:

.venv\Scripts\activate pip install -r requirements.txt
